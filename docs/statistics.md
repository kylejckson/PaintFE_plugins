# Popular and Trending

Popular ranks packs by cumulative GitHub Release asset downloads across their published versions. Trending ranks the recorded growth over a seven-day window. During the first week, the browser identifies the shorter period recorded. Figures count downloads, not unique users, successful installs or app usage; retries and maintainer tests can count.

A trusted scheduled workflow takes snapshots approximately every six hours and after publication. It tracks immutable GitHub asset IDs, keeps older totals, handles replaced/reset counters and bounds the rolling sample history. Missing history is not invented. The browser displays the catalogue's last update time and remains usable when statistics are stale.

Only `.pfeplugin` assets count. Screenshots and icons do not count. Multi-effect packs have one download total, not a separate invented total for each effect. No requests are sent from the app to measure installation or use.

Schedules can be delayed by GitHub, and public-repository schedules can be disabled after inactivity. Maintainers can run Refresh download statistics manually. Never show a stale snapshot as real-time activity.
